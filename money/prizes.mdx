---
title: "Prizes"
description: "Host-funded prizes that Zend holds until your server says who won."
---

A host puts up a prize, players join for free, and your server decides the winners. Zend's prize rules hold the money until then. Entry fees and stakes aren't available.

## Setup

<Steps>
  <Step title="Generate a resolver key">
    ```bash
    zend apps resolver-key
    ```

    Put the printed `resolverKey` in your manifest. Keep `ZEND_RESOLVER_SEED` on your server only; it signs results.
  </Step>
  <Step title="Update the manifest">
    Add the `prize` permission and set `results` to `"app"` or `"checked"`:

    ```json
    {
      "permissions": ["prize"],
      "results": "app",
      "resolverKey": "3b6a27bc…"
    }
    ```
  </Step>
</Steps>

## Lifecycle

```text
create (host funds) → join (players, free) → resolve (your server signs)
   → wait (dispute window, at least 10 min) → paid

During the wait: your server can correct the result once; the host can cancel (everything back to host).
No result by the resolve deadline: everything back to host.
```

## Timing

| Setting | Rule |
|---|---|
| `joinInSecs` | At least 60. Joining closes at this time |
| `resolveInSecs` | The results deadline. Must be later than `joinInSecs`, and at most 30 days |
| `disputeSecs` | The wait after results. Default 3600 (1 hour). Values under 600 are raised to 600 (10 minutes). At most 7 days |
| `maxPlayers` | 1–500 |

Times count from when the host creates the prize. A time outside these rules fails with `INVALID_DEADLINES`, and `maxPlayers` outside 1–500 with `INVALID_MAX_PLAYERS`.

- Your server can send the first result only after joining closes (`TOO_EARLY`, with the closing time) and before the results deadline (`RESULT_DEADLINE_PASSED`).
- The dispute window starts when Zend accepts the result. A correction starts it again.
- When the window ends, Zend pays the winners. When the results deadline passes with no result, Zend returns the whole prize to the host. Zend checks for both about every 60 seconds, so expect up to a minute's delay.
- The host can cancel only during the dispute window. Cancelling returns the whole prize to the host (`prize.refunded` with `reason: "vetoed"`). Before results, or after the window, it fails with `WINDOW_CLOSED`.

## In your page

```ts
const prize = await zend.prize.create({
  amount: 20,
  joinInSecs: 3600,
  resolveInSecs: 86400,
  maxPlayers: 32,
  disputeSecs: 3600,
  reference: "tournament_9",
  interactionId,
});

await zend.prize.join(prize.id);   // players
await zend.prize.get(prize.id);
await zend.prize.cancel(prize.id); // host, only during the wait after results
```

`amount` is in US dollars (at least 1), or pass `price: { ngn }`. Zend shows the rules before the host confirms.

## On your server

```ts
import { ZendServer } from "@zendfi/appkit/server";

const zend = new ZendServer(process.env.ZEND_APP_KEY!);

const p = await zend.getPrize(prizeId); // p.players: [{ address, app_user_id }]
const first = p.players.find((x) => x.app_user_id === winnerId).address;

await zend.resolvePrize(prizeId, [first], [20], process.env.ZEND_RESOLVER_SEED!);

// Made a mistake? Once, during the wait:
await zend.resolvePrize(prizeId, [other], [20], process.env.ZEND_RESOLVER_SEED!, true);
```

Zend and the prize contract both check that:

- Winners joined the prize.
- No winner appears twice.
- There are at most 50 winners.
- The amounts add up to no more than the prize. Anything left over returns to the host.

## Webhooks

| Event | When |
|---|---|
| `prize.created` | The host funded it. `data` is the prize |
| `prize.joined` | A player joined: `{ prize_id, by }`, where `by` is their `appUserId` |
| `prize.resolved` | Zend accepted your server's result or correction: `{ prize, digest }` |
| `prize.paid` | The wait ended and winners were paid: `{ prize, reason: "finalized", digest }` |
| `prize.refunded` | The whole prize returned to the host: `{ prize, reason, digest }`. `reason` is `vetoed` (host cancelled) or `no_result` (no result by the deadline) |

See [Webhooks](/reference/webhooks#events) for the fields of `prize`.

## Limits

A prize is at least $1. The largest prize is the lower of your tier's maximum and a Zend-wide cap, currently $20:

| Tier | Tier maximum | Largest prize today |
|---|---|---|
| private | $20 | $20 |
| public | $100 | $20 |
| growth | $500 | $20 |

A bigger prize fails with `APP_LIMIT_AMOUNT`, and a smaller one with `BELOW_MINIMUM`.
