title: "REST API"
description: "HTTP endpoints for your backend and for app setup."
---

Base URL: `https://api.usezend.app/api/zend/v2`. Requests and responses are JSON.

## Authentication

| Credential | Header | Used for |
|---|---|---|
| App key | `Authorization: Bearer zapp_sk_...` | Your backend. Never send it to browsers |
| User session | `Authorization: Bearer <Zend session>` | App setup, called as you |
| None | | Public attestation endpoints |

Most setup is easier with the [CLI](/cli/apps), which calls these endpoints for you.

Errors look like:

```json
{ "error": "INVALID_TRANSITION", "message": "..." }
```

`INVALID_MANIFEST` also includes `errors[]`. See [Errors](/reference/errors).

## Your backend (app key)

| Method | Path | Body or query | Returns |
|---|---|---|---|
| POST | `/apps/token/verify` | `{ app_session }` | The verified user. See [Sign in with Zend](/guides/identity) |
| POST | `/apps/server/interactions` | `{ type, created_by, participants?, data?, visibility?, expires_in_secs? }` | The interaction |
| GET | `/apps/server/interactions/:id` | | The interaction |
| PATCH | `/apps/server/interactions/:id` | `{ state, data?, idempotency_key, expected_version? }` | The interaction |
| GET | `/apps/server/payments` | `?reference=` | `{ payments: [...] }`, up to 50, newest first |
| GET | `/apps/server/events` | | The last 100 webhook events with `delivered_at` |
| POST | `/apps/server/random` | `{ interaction_id, label, kind, n, k? }` | The draw. See [Random draws](/fairness/random-draws) |
| GET | `/apps/server/prizes/:id` | | The prize with `players` |
| POST | `/apps/server/prizes/:id/resolve` | `{ winners, amounts, signature, correction }` | The prize. Use `resolvePrize` from the server SDK |
| PUT | `/apps/server/manifest` | Manifest JSON | Deploys your own app's manifest. Used by `zend apps deploy` in CI |
| PUT | `/apps/server/icon` | The image (`Content-Type: image/png`, `image/jpeg` or `image/webp`) | `{ status, icon_url }` or `{ status: "pending_review", pending_icon_url }`. See [App icon](/guides/app-icon) |
| GET (WebSocket) | `/apps/server/live/:interaction_id/ws` | | A [live room](/guides/live-rooms#from-your-server) connection |
| POST | `/apps/server/people/blocked` | `{ app_user_ids }` (2–50) | `{ pairs: [[a, b], …] }`. See [Keep blocked people apart](/guides/people#keep-blocked-people-apart) |
| POST | `/apps/server/unlock/listings` | `{ item, title?, to, amount_usd? \| price: { ngn }, splits? }` | `201` the listing, or `202 { status: "pending" }`. See [Pay-to-read](/money/unlock) |
| GET | `/apps/server/unlock/listings/:item` | | The listing |
| PATCH | `/apps/server/unlock/listings/:item` | `{ active?, title?, to?, amount_usd?, price?, splits? }` | The listing |
| GET | `/apps/server/unlock/access` | `?item=&user=zu_…` | `{ item, unlocked }` |

`created_by` is `@username` or `zu_...`, and that user must have connected your app.

## App setup (user session)

| Method | Path | Body | Notes |
|---|---|---|---|
| POST | `/apps` | `{ slug, name }` | Returns `api_key` and `webhook_secret` once. Max 10 apps per account. Upload the icon separately |
| GET | `/apps` | | Your apps |
| PUT | `/apps/:id/manifest` | Manifest JSON | New version. `public` goes to `in_review` |
| PUT | `/apps/:id/icon` | The image | Same as `/apps/server/icon`. See [App icon](/guides/app-icon) |
| POST | `/apps/:id/testers` | `{ zendtag }` | The owner is always a tester |
| POST | `/apps/:id/rotate` | `{ which: "api_key" \| "webhook_secret" \| "both" }` | New values, shown once. Old ones stop working immediately |
| GET | `/apps/:id/review` | | Review status and findings |
| PUT | `/apps/:id/payout` | `{ username }` | Where your app's share of split payments goes |

Slugs are 2–31 characters of `a-z`, `0-9` and `-`.

## Public

| Method | Path | Returns |
|---|---|---|
| GET | `/apps/attest/key` | `{ alg, public_key }`, Zend's attestation key |
| GET | `/apps/attest/interactions/:id` | `{ receipts: [...] }` for an interaction |
| GET | `/apps/listed` | Listed public apps |

## Bot accounts

Creation, from the CLI:

| Credential | Method | Path | Notes |
|---|---|---|---|
| None (rate limited per IP) | POST | `/api/v1/bots/sessions` | `{ bot_name, handle, address, scopes? }`. Returns `{ session_id, approval_url, expires_at }` |
| None | GET | `/api/v1/bots/sessions/:id` | `{ status }`: `pending`, `approved`, `denied` or `expired` |
| None | POST | `/api/v1/bots/sessions/:id/key` | `{ api_key }`, once |

The bot itself, with `Authorization: Bearer zbot_live_...`:

| Scope | Method | Path | Notes |
|---|---|---|---|
| `read` | GET | `/api/v1/bot/me` | Profile, scopes and limits |
| `read` | PATCH | `/api/v1/bot/me` | `{ display_name }`, 1–40 characters |
| `read` | GET | `/api/v1/bot/balance` | The bot's balance |
| `read` | GET | `/api/v1/bot/dm` | The bot's chats |
| `dm_send` | POST | `/api/v1/bot/dm/with/:handle` | Opens a chat. Returns `{ room_id, counterparty }` |
| `read` | GET | `/api/v1/bot/dm/:room_id/messages` | Query `cursor`, `limit` (max 100). Direct chats only |
| `dm_send` | POST | `/api/v1/bot/dm/:room_id/messages` | `{ content, client_id? }`. Text only |
| `read` | POST | `/api/v1/bot/dm/:room_id/read` | `{ last_message_id }` |
| `send_money` | POST | `/api/v1/bot/pay/prepare` | `{ to, amount }`. Returns `{ transaction_data_bcs, expires_in }` |
| `send_money` | POST | `/api/v1/bot/pay/submit` | `{ transaction_data_bcs, signature, note? }`. Only prepared bytes, once |
| `send_money` | POST | `/api/v1/bot/pay/deposit/prepare` | Builds the step that makes received funds spendable |
| `send_money` | POST | `/api/v1/bot/pay/deposit/submit` | `{ transaction_data_bcs, signature }` |
| `post_card` | POST | `/api/v1/bot/posts` | `{ text, client_id? }`. Returns `{ id }` |
| `post_card` | DELETE | `/api/v1/bot/posts/:id` | Removes one of the bot's posts |

These paths start at `https://api.usezend.app`, not under `/api/zend/v2`. [`zend bot`](/cli/bot) calls them for you. See [Bot accounts](/bots) for the payment steps and errors.

The Zend app calls these on the owner's behalf, with the owner's own session. They aren't for your code:

| Method | Path | Notes |
|---|---|---|
| GET | `/api/zend/bots` | The owner's bots, with limits, posting and paused state |
| GET | `/api/zend/bots/sessions/by-code/:code` | What the approval screen shows |
| POST | `/api/zend/bots/sessions/:id/approve` / `deny` | Make or cancel a bot. Needs a person who passed the verified check and a fresh confirmation |
| PATCH | `/api/zend/bots/:id/settings` | Limits, allowed recipients, first contact, requests a minute |
| POST | `/api/zend/bots/:id/posting` | `{ enabled }` |
| POST | `/api/zend/bots/:id/suspend` / `resume` | Pause or resume |

## Endpoints the Zend client uses

`/apps/by-slug/:slug/*` (including `unlock/*`), `/apps/interactions`, `/apps/cards`, `/apps/feed`, `/apps/prizes/*`, `/apps/people/connect`, `/apps/people/chat`, `/seal/*`, `/me/connected-apps` and the live room socket for users are called by the Zend app on your page's behalf. You reach them through the client SDK; don't call them directly.
