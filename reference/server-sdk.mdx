```ts
import { ZendServer, verifyWebhook, verifyAttestation } from "@zendfi/appkit/server";

const zend = new ZendServer(process.env.ZEND_APP_KEY!);
```

<Warning>
Your app key (`zapp_sk_...`) is a server secret. Never send it to a browser or put it in your page bundle.
</Warning>

## new ZendServer(apiKey, baseUrl?)

<ParamField body="apiKey" type="string" required>
  Your app key, from `zend apps create` or `zend apps rotate-key`.
</ParamField>

<ParamField body="baseUrl" type="string" default="https://api.usezend.app">
  API host. Change it only for a non-production environment.
</ParamField>

Failed calls throw an `Error` with `code` (Zend's error code) and `status` (HTTP status).

## verifySession(appSession)

Exchange the `appSession` from `zend.identity.get()` for the verified user.

```ts
const user = await zend.verifySession(appSession);
// { app_user_id, username, name, avatar, human_verified, scopes, email?, address? }
```

See [Sign in with Zend](/guides/identity).

## createInteraction(params)

Create an interaction on behalf of a user who has connected your app.

```ts
await zend.createInteraction({
  type: "challenge",
  created_by: "@tunde",          // or zu_...
  participants: ["@danny"],
  data: { round: 1 },
  visibility: "participants",
  expires_in_secs: 3600,
});
```

## getInteraction(id)

```ts
const it = await zend.getInteraction("int_...");
```

## updateInteraction(id, params)

Move an interaction along. Your server can make `serverOnly` moves that pages can't.

```ts
await zend.updateInteraction(id, {
  state: "resolved",
  data: { winner: "zu_..." },
  idempotency_key: `${id}:resolve`,
  expected_version: 3,
});
```

## blockedPairs(appUserIds)

Of 2–50 players, the pairs that must not share a room because one blocked the other. Pairs are sorted, so you can't tell who blocked whom.

```ts
const { pairs } = await zend.blockedPairs(["zu_…", "zu_…", "zu_…"]);
```

See [Keep blocked people apart](/guides/people#keep-blocked-people-apart).

## createListing(params)

Puts an item on sale for [pay-to-read](/money/unlock). Needs the `unlock` permission.

```ts
const listing = await zend.createListing({
  item: "issue-42",
  title: "The Lagos Dispatch, issue 42",
  price: { ngn: 500 },                  // or amount_usd
  to: "@ada",                           // or "app"
  splits: [{ to: "app", percent: 10 }],
});
```

Returns the listing. A `202 { status: "pending" }` means send the same request again shortly.

## getListing(item) / updateListing(item, params)

```ts
await zend.getListing("issue-42");
await zend.updateListing("issue-42", { active: false });
await zend.updateListing("issue-42", { to: "@ada", price: { ngn: 800 }, splits: [{ to: "app", percent: 10 }] });
```

To reprice, give `to`, the price and `splits` together.

## hasAccess(item, appUserId)

```ts
const { unlocked } = await zend.hasAccess("issue-42", "zu_…");
```

Whether that person holds a receipt for the item right now, checked on Sui. A purchase or gift made through Zend in the last 5 minutes counts straight away.

## requireAccess(appSession, item)

```ts
const user = await zend.requireAccess(req.header("x-zend-session")!, "issue-42");
```

`verifySession` plus `hasAccess` in one call. Returns the verified user when they hold a receipt. Throws an error with `code: "NO_ACCESS"` and `status: 403` when they don't. See [Serve the content](/money/unlock#2-serve-the-content-server).

## getPrize(id)

The prize and every joined player's `address` and `app_user_id`.

## resolvePrize(id, winners, amountsUsd, resolverSeedHex, correction?)

Signs the result with your resolver key and posts it.

| Param | Notes |
|---|---|
| `winners` | Player addresses from `getPrize().players` |
| `amountsUsd` | One amount per winner, in US dollars |
| `resolverSeedHex` | Your `ZEND_RESOLVER_SEED` |
| `correction` | `true` to correct a result once, during the dispute window |

Payout happens after the dispute window unless the host cancels. See [Prizes](/money/prizes).

## Devices your app runs

```ts
createDevice({ name, hardware?, max_request_ngn? }): Promise<{ device_id, device_key, signing_secret, name }>
listDevices(): Promise<{ devices: { id, name, hardware, last_seen_at, paused, config }[] }>
setDeviceConfig(id, config): Promise<{ ok: true }>
sendDeviceCommand(id, name, args?): Promise<{ id, status: "sent" }>
removeDevice(id): Promise<{ ok: true }>
```

The key and signing secret come back once, from `createDevice`. Payments to these devices go to your app's payout account, and their events reach your webhook as `device.<type>`. See [Devices](/devices#devices-your-zapp-runs).

## verifyDeviceReading(receipt, zendPublicKeyHex)

`true` when `sha256(receipt.signed_body) == receipt.reading_hash` and `receipt.signature` is Zend's Ed25519 signature over it. Get `zendPublicKeyHex` from `GET /api/zend/v2/apps/attest/key` (`public_key`). Then read values from `JSON.parse(receipt.signed_body)`. See [Signed readings](/devices#signed-readings).

## verifyWebhook(rawBody, header, secret, toleranceSecs?)

Returns `true` when `x-zend-signature` matches the raw body and is no older than `toleranceSecs` (default 300). Pass the raw body, before JSON parsing. See [Webhooks](/reference/webhooks#verify-signatures).

## verifyAttestation(receipt, zendPublicKeyHex)

Returns `true` when an attestation receipt's hash and Zend's signature are valid. Get the key from `GET /apps/attest/key`. See [Attestations](/fairness/attestations).

## resolverKeyFromSeed(seedHex)

Returns `{ privateKey, publicKeyHex }` for a 32-byte hex seed. `publicKeyHex` is the value for `resolverKey` in your manifest. `zend apps resolver-key` does this for you.

## UNLOCK_SEAL and unlockIdentity(listingId, suffix?)

For encrypted content, [coming later](/money/unlock#encrypted-content-coming-later). Seal settings and the identity to encrypt pay-to-read content under:

```ts
import { UNLOCK_SEAL, unlockIdentity } from "@zendfi/appkit/server";

UNLOCK_SEAL.packageId;     // Zend's unlock package on Sui mainnet
UNLOCK_SEAL.committee;     // Seal's mainnet committee; use threshold 1
UNLOCK_SEAL.aggregatorUrl;
unlockIdentity(listing.listing_id, "chapter-2"); // hex, no 0x
```

Not needed for pay-to-read today.

## prizeResultMessage(prizeId, winners, amounts, correction?)

The exact bytes your resolver key signs, matching `zend::prize::result_message`. `resolvePrize` uses it; you only need it if you sign results somewhere else.
