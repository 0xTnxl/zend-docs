Set `webhook` in your [manifest](/guides/manifest) to an `https` URL. Zend POSTs JSON to it:

```json
{
  "id": "6f1c…",
  "type": "payment.completed",
  "created_at": "2026-11-02T10:00:00Z",
  "data": { }
}
```

Headers:

| Header | Value |
|---|---|
| `x-zend-signature` | `t=<unix seconds>,v1=<hex>` |
| `x-zend-event-id` | The event `id` |

## Events

| Type | `data` |
|---|---|
| `interaction.created` | The interaction |
| `interaction.updated` | The interaction after the change |
| `payment.completed` | A `pay`: `{ payment_id, from, to, amount_usd, price_ngn, ngn_per_usd, rate_id, reference }`. Split payments and pay-to-read purchases add `parts` and `transaction_id`. An ask link payment: `{ ask_link_id, from, to, amount_usd, reference }`, plus `"method": "bank_transfer"` when paid by bank transfer |
| `link.claimed` | `{ link_id, by, amount_usd, reference }` |
| `random.drawn` | A [draw](/fairness/random-draws) finished: `{ interaction_id, label, kind, n, k, value, transaction_id, attestation, verify: { package, registry } }`. Sent once per draw, whether a page or your server asked |
| `people.connected` | `{ from, to, interaction_id, mutual, at }`. `from` added `to`; `mutual` is `true` when `to` had already added `from` |
| `device.payment.received` | A device your app runs was paid: the [device event](/devices#events) `data` plus `device_id` |
| `device.checkin` | Someone checked in at one of your devices |
| `device.reading` | `{ device_id, receipt }`. Check `receipt` with `verifyDeviceReading` before using it |
| `device.command` / `device.config.updated` | You sent a command or changed settings (a copy of what the device got) |
| `device.command.acked` | `{ device_id, command_id, name, ok, message }`: the device answered a command |
| `unlock.listed` | The [listing](/money/unlock) |
| `unlock.bought` | `{ item, listing_id, receipt_id, payment_id, by, for, amount_usd, transaction_id }`. `receipt_id` can be `null` |
| `unlock.gifted` | `{ item, listing_id, receipt_id, from, to, transaction_id }` |
| `prize.created` | The host funded a [prize](/money/prizes). `data` is the prize |
| `prize.joined` | A player joined: `{ prize_id, by }` |
| `prize.resolved` | Zend accepted your server's result, or its one correction: `{ prize, digest }`. The dispute window starts now |
| `prize.paid` | The dispute window ended and the winners were paid: `{ prize, reason: "finalized", digest }` |
| `prize.refunded` | The whole prize went back to the host: `{ prize, reason, digest }`. `reason` is `vetoed` (the host cancelled during the dispute window) or `no_result` (no result by the results deadline) |

`from`, `to`, `by` and `for` are `appUserId`s. `by` on `link.claimed` is `null` if the collector has never connected your app. `price_ngn`, `ngn_per_usd` and `rate_id` are `null` unless the payment was priced in Naira.

`prize` (and `data` on `prize.created`) is `{ id, app, app_name, host, pot_usd, pot_ngn, max_players, player_count, join_deadline, resolve_deadline, dispute_secs, dispute_ends, status, winners, corrected, reference, interaction_id, joined, is_host, kind }`, the same shape `zend.prize.get` returns. In webhooks, `joined` and `is_host` are always `false`. `status` is `open`, `resolved`, `paid` or `refunded`. `kind` is `prize` or `hold`. `winners` is `[{ address, amount_usd, app_user_id }]` once there's a result. `digest` is the Sui transaction digest of the step that changed the prize.

## Verify signatures

`v1 = hex(HMAC-SHA256(webhook_secret, "<t>.<raw body>"))`. Use the raw request body, before JSON parsing.

<CodeGroup>
```ts Express
import express from "express";
import { verifyWebhook } from "@zendfi/appkit/server";

app.post("/zend/webhook", express.text({ type: "*/*" }), (req, res) => {
  if (!verifyWebhook(req.body, req.header("x-zend-signature") ?? "", process.env.ZEND_WEBHOOK_SECRET!)) {
    return res.sendStatus(401);
  }
  const event = JSON.parse(req.body);
  // dedupe on event.id, then handle
  res.sendStatus(200);
});
```

```ts Any runtime
import { createHmac, timingSafeEqual } from "node:crypto";

function verify(rawBody: string, header: string, secret: string): boolean {
  const parts = Object.fromEntries(header.split(",").map((kv) => kv.split("=")));
  const t = Number(parts.t);
  if (!parts.v1 || Math.abs(Date.now() / 1000 - t) > 300) return false;
  const expected = createHmac("sha256", secret).update(`${t}.${rawBody}`).digest();
  const given = Buffer.from(parts.v1, "hex");
  return expected.length === given.length && timingSafeEqual(expected, given);
}
```
</CodeGroup>

`verifyWebhook` rejects signatures older than 5 minutes. Rotate the secret with [`zend apps rotate-key --webhook-secret`](/cli/apps#rotate-key).

## Delivery

- Any `2xx` response is success. Anything else, or no response within 10 seconds, is retried.
- Retries back off from 30 seconds, doubling, for up to 12 attempts (about a day), then stop.
- Events can arrive more than once and out of order. Dedupe on `id`, and use the interaction's `version` to ignore stale updates.

## Catch up

```bash
curl https://api.usezend.app/api/zend/v2/apps/server/events \
  -H "Authorization: Bearer $ZEND_APP_KEY"
```

Returns the last 100 events with `delivered_at`, so you can replay what you missed.
